主要估計量為項目內差值的平均。CI 是 10,000 次項目 bootstrap 的百分位區間；Wilcoxon 是補充性的符號秩檢定，與平均差 CI 的虛無假設不同。p 值未作多重比較校正；子類別分析屬探索，n 很小時區間不穩定。不顯著不等於無效果，區間跨零也不代表兩條件等價。

精確的基準路徑：直接差異如何相加？

台繁 − 中簡 =（台簡 − 中簡）＋（台繁 − 台簡）。這是同一批項目的算術恆等式；三地平均字形效果與台中平均詞彙效果不能直接當成這條路徑的兩個貢獻。

讓每一個 token 的 bytes 都可檢查

紅框表示該 token 的 bytes 無法單獨解碼為完整 UTF-8 字串。它可能包含多個位元組，也可能跨過字元邊界；這個觀察本身不能證明某個漢字缺少專屬 token。

字元位置與 token 邊界如何對齊？

兩者使用同一組 UTF-8 byte 座標。token 區間是左閉右開 [start, end)；將所有 token bytes 串起來，必須完全還原輸入。

覆蓋率、合併順位、前置切分與上下文都可能影響結果。「單字未收錄」與「這次被切開」要分開查驗；單字未收錄也可能被包含在多字 token 中。

查的是詞表形式，推論要留在證據範圍內

比例的分母是「已在詞表中、且 OpenCC 會轉成不同繁／簡對應形式的單漢字」。不是所有繁體字的缺漏率。只計完全匹配的漢字 bytes，沒有把含前後空白的 token 當成單字。OpenCC 對應不是唯一的語言學字形標準。

檢視最長的純漢字條目（可能含廣告及成人內容）

條目可作為資料來源的線索，但不能只靠長度或排名推回訓練語料的比例、日期或實際頻率。提出來源假設後，還需要獨立資料驗證。

token 邊界與構式邊界，是兩個問題

下表量的是具體字串是否成為一個 token，及表面變體的切分。相同字串的兩欄是重複參照；其他配對也不全是語義最小對比。BPE 詞表並非形式—意義配對的構式庫。

「洗澡」是兩個 token，模型還能理解它嗎？

這裡的資料無法回答。可另做釋義判斷、插入成分的泛化及語義最小對比測試，並記錄模型版本、提示、重複次數與人工評分。將「邊界一致」與「掌握構式」分別提出假設。

把觀察換成明確的使用情境

價格與 context 屬於具體模型與服務方案，不屬於 tokenizer。本表使用你設定的假設情境；預設值不是任何供應商的現行報價。費用只計輸入，context 扣除你預留的提示與輸出額度。

換算率 = Σ tokens / Σ 所選字數，並非句子比率的平均。連接文本會改變切分邊界，因此 context 容量只是以本材料校準的近似值。混排文本若選漢字分母，非漢字的 tokens 也在分子，不能解讀為單一漢字的切分成本。
